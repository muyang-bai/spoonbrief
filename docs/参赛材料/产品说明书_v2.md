## 一、我们解决什么问题

信息过载不是"信息太多"，而是**每天 700+ 条热点里，与你真正相关的不到 10 条**，而你要花 40 分钟把它们翻出来。

现有产品的三种做法都不够：

| 做法 | 问题 |
|---|---|
| 资讯 App / 热搜榜 | 按大众热度排序，不是按"你"排序 |
| RSS /  Newsletter | 只做聚合，需要你自己判断重要性 |
| 通用 AI 总结 | 每天把同样的新闻重新总结一遍，读起来"像新的"，其实没有新增信息 |

一勺热点的主张：**每天一封，只讲与你有关、且这次真的新增了什么。**

## 二、目标用户与场景

| 用户 | 场景 | 他们真正要的 |
|---|---|---|
| 创业者 / 一人公司 | 早上 10 分钟决定今天做什么 | 机会、风险、可执行动作 |

| 考研 / 求职学生 | 专业方向与政策变化 | 与自身路径相关的变化 |
| 内容创作者 | 找选题 | 有增量的事实与角度 |

产品形态：**订阅一个方向 → 每天定时收到一封邮件 → 邮件里能读完、能点原文、能反馈有用没用。**

## 三、产品逻辑链路（端到端）

```
① 订阅配置
   方向关键词 / 时间窗 / 频率 / 分析模板 / 无更新策略
        │
        ▼
② 调度（Celery Beat，每分钟）
   扫描 next_sent_at 到期 → 防重派发（15 分钟内 running 跳过）
   到期超 24 小时不补发，直接滚动到下次（防重启后邮件轰炸）
        │
        ▼
③ 信息池（每 30 分钟常驻抓取）
   19 个信源（IT之家 / 财新 / 量子位 / 中新网 / 界面 …）
   RSS/接口 → 指纹去重 → 可信度打分 → 入库 news_items
        │
        ▼
④ 素材筛选
   关键词/画像命中 → 时间窗过滤 → 与上一期文章去重 → 按新鲜度与相关度排序
   用户自定义 RSS 源并入（个人源池）
        │
        ▼
⑤ 事件级新颖性判定（本产品核心差异点）
   ├─ 同事件多篇报道合并为一组，保留全部出处
   ├─ 与订阅的历史事件记忆比对（跨期、可模糊匹配）
   ├─ 判定：全新事件 / 实质进展 / 重复报道
   │    · 实质进展 = 出现「新来源 + 新日期或新数据」
   │    · 纯转载、换标题、AI 重新总结 → 判为重复，不推送
   └─ 结果：fresh / progress / repeat 三分类 + 计数写入报告
        │
        ▼
⑥ 无重要更新时（由用户选择）
   · 跳过本次（skip）：不发信，只记录
   · 周期汇总（digest）：发一封「本周期回顾」，列出已覆盖事件、首次出现时间、来源数
   · 照常推送（always）：接受重复
        │
        ▼
⑦ AI 分析
   按订阅选定的「分析模板」（默认分析师 / 投资视角 / 创业视角 / 行业深度 / 竞品情报 / 每日精读）
   单次调用产出分析师全文；引用编号绑定到素材，禁止编造来源
        │
        ▼
⑧ 决策层（第二次轻量 JSON 调用）
   一句话结论 / 30 秒速览 / 每条素材的情绪（利好·利空·中性）与影响分（1–10）
   今日行动清单 / 五维影响（个人财务·职业发展·学业成长·政策合规·行业趋势）
        │
        ▼
⑨ 邮件渲染与发送
   浅色蓝版式（#5B7CFF）、图文结构、可点击原文、五星信源等级（附评级依据）
   事件进展区块（上次 → 这次新增）、周期汇总版式、退订与合规信息
   SMTP 实发 → 记录发送时间与状态
        │
        ▼
⑩ 反馈与下一期
   邮件底部「有用 / 没用」；点「没用」→ 选择原因（方向不相关 / 太浅 / 太旧或重复 / 依据不足 / 太长）
   下一期生成时读取最近反馈，注入分析提示：减少已报道内容、提高门槛、补充背景与影响、控制篇幅
   负反馈只影响随后几期，不做永久屏蔽；没有反馈不视为满意
        │
        ▼
⑪ 双产品联动
   与 AiLifeOS 共库、HMAC 互通：同邮箱自动绑定账号
   简报同步到 AiLifeOS App「今天 → 邮箱简报」，会员与额度由 AiLifeOS 统一管理
```

技术选型：Python 3.11 + FastAPI、Celery 5 + Redis、MySQL 8、Vue 3 + Vite、DeepSeek（deepseek-flash）、Docker Compose、宝塔 nginx、Let's Encrypt。

工程要点：
- **可靠调度**：派发前检查 running 任务、到期超 24h 不补发、看门狗 15 分钟自愈孤儿任务
- **配置安全**：AI Key 与 SMTP 授权码落库前 Fernet 加密（`enc:v1:` 前缀），后台读写自动加解密
- **性能**：静态资源 immutable 一年缓存、登录态 GET 接口 Redis 30 秒缓存（写操作版本号失效）、首页 TTFB ≈ 0.05s
- **可运维**：每日 03:00 数据库备份（保留 8 份 + 第二副本 + rclone 异地钩子）、容器镜像按版本打标可回滚

## 七、与同类产品的差异

| 维度 | 资讯 App | 通用 AI 总结 | 一勺热点 |
|---|---|---|---|
| 排序依据 | 大众热度 | 模型觉得重要 | 你的画像 + 关键词 + 历史 |
| 重复内容 | 反复出现 | 每天重述同一批新闻 | **事件级去重，只推新增与进展** |
| 无更新时 | 继续推送 | 硬凑一篇 | **可选跳过或周期汇总** |
| 可信度 | 无标注 | 常无出处 | **五星信源 + 原文链接 + 评级依据** |
| 反馈 | 不透明 | 不影响下一次 | **归因后进入下一期生成** |
| 成本 | — | 按次计费较高 | 单封约 ¥0.02 |

一句话：**别人做"今天有什么"，我们做"今天有什么是新的、和你有关、你该怎么办"。**

## 十、合规与边界

- AI 内容标注："AI 辅助分析，不是来源原文或已核实结论"
- 信源星级只表示**来源类型可溯性**，不代表真实性概率
- 不构成投资建议；涉及决策请回原文核对
- 每封邮件独立退订令牌；退订即时生效
- 用户画像与反馈仅用于本产品个性化，不对外共享
