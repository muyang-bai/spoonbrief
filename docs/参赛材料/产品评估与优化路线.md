## 二、问题清单（按严重程度）

### P0 · 影响"有没有用"的判断

1. **事件记忆靠标题相似度，实体未归一化**
   - 现状：`国产算力芯片…` 与 `国产算力芯片单月出货 120 万片` 相似度 0.286，靠包含度阈值才匹配上。
   - 风险：同一公司不同措辞（如"腾讯"与"Tencent"）、政策文件简称与全称，可能漏判成"新事件"。
   - 建议：引入实体词表（公司/产品/政策名）+ 别名词典，事件键 = 主体 + 动作类型。

2. ~~反馈样本太小、「有用率」不可信~~（2026-11-22 已补：原因选择页 + 原因分布看板，见"已完成"）
   - 现状：up 1 / down 1，50%。
   - 风险：无法据此判断产品价值；单条负反馈会显著影响提示注入。
   - 建议：反馈原因选择页上线（接口已支持 reason，邮件里还只有两个按钮）；加"这期你学到什么"可选一句话；按周聚合而非单条。

3. **评测指标只落库、未形成看板**
   - 现状：`decision_json._novelty` 有 fresh/progress/repeat，但管理端看不到趋势。
   - 建议：用量页增加"去重效率曲线"（repeat 占比）、"进展命中率"、"0 新增触发次数"。

### P1 · 体验与成本

4. ~~每封简报两次模型调用~~（2026-11-22 已合并为一次调用，实测单封 1 条 token 记录）
   - 分析一次 + 决策层一次（约 1–2k tokens）。单封 ¥0.02 已经很便宜，但可合并为一次结构化输出，预计省 30–40% 成本、缩短 15–20 秒。

5. ~~信源健康度没有闭环~~（2026-11-22 已实现：连续失败 3 次自动停用并记录原因）
   - 19 个源里 5 个长期停用；单源失败只记日志，不降权、不摘除。
   - 建议：连续 N 次失败自动降权/停用并通知管理员；后台展示每源成功率。

6. ~~无更新时「跳过」没有回执~~（2026-11-22 已实现：可开关的「今日无新增」短通知）
   - 选 `skip` 时用户当天什么都收不到，容易以为产品挂了。
   - 建议：跳过时发一封 3 行短通知（或 App 内提示），说明"今天没有值得打扰你的新增"。

7. **浅色蓝版式在暗色邮箱客户端对比度不足**
   - 建议：`@media (prefers-color-scheme: dark)` 兜底，或加深正文文字到 #1A1F36。

### P2 · 增长与形态

8. **只有邮件一个出口**
   - App 内已有「今天 → 邮箱简报」，但没有微信服务号 / PWA 推送，触达面受限。

9. **简报不可分享**
   - 建议：生成只读分享页（带来源与免责声明），支持"订阅同款方向"。

10. **演示与转化路径偏长**
    - 落地页 → 注册 → 填画像 → 建订阅，四步。建议提供 3 个一键模板（AI 从业者/考研/投资），注册即预填。

## 四、风险与边界

- **内容准确性**：AI 输出可能过度推断；已用"分析师全文与素材分离""引用编号绑定""五星≠真实性"三条约束降低风险，仍需人工抽检。
- **信源依赖**：RSS/接口随时可能失效；已有多源冗余，但需健康度闭环。
- **合规**：AI 生成内容标注、投资建议免责、退订即时生效均已实现。
- **单点**：目前单机部署（nginx + 5 容器 + MySQL），无多可用区；赛事/初期规模可接受，商业化前需做读写分离与备份异地化（备份异地钩子已就绪，待接对象存储）。

## 五、一句话判断

**产品已经过了"能不能跑"的阶段，进入"能不能证明有用、能不能规模化"的阶段。**
下一步最该做的不是加功能，而是把"新颖性判定"和"反馈归因"两件事做扎实——这正是它与"又一个 AI 新闻摘要"的分水岭。
