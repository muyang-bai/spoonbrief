# 一勺热点 项目说明书（技术与原理）

> 一句话定位：**全网热点，AI 分析后喂到你嘴边——可溯源、个性化、定时送达的 AI 情报简报**
> 本稿仍按早期 PostgreSQL 六服务口径书写，不是 2026-11-27 现网。现网是 MySQL 8（与 AiLifeOS 共库）、Compose 五服务；镜像钉扎见 README。产品现状以 `docs/参赛材料/产品说明书_v2.md` 与 README 为准。

**架构图（文字版）**

```
用户 ──HTTPS──> Nginx ──> 前端容器(静态+API代理) ──> 后端 FastAPI
```

## 二、工作原理（五步流水线）

### 1. 数据供给（信息池）
- 每 30 分钟从 **14 个 RSS 信源**（IT之家/财新网/中新网/开源中国等）抓取新闻入库（`news_items` 表，约 700+ 条滚动更新）
- **语义归并**：同一条新闻被多家媒体报道时合并为"事件"（`news_events`）——用 15 字标题指纹 + jieba 分词交集（≥2）+ 字符 2-gram 相似度（Dice ≥ 0.40）三级判定，这就是"多源交叉验证"的数据基础

### 2. 个性化匹配（相关性打分）
- 用户订阅带关键词（如"苹果折叠屏，苹果Duo"）+ 身份画像（学生/创业者/投资者/创作者）
- 查询信息池时做**分词级匹配**：整词命中标题 +5 分、词元命中 +2/+1 分、≥2 词元命中才算匹配
- 结果分两层：**「与你相关」**（命中关键词/画像）和**「今日要闻」**（广度兜底）

### 3. AI 全局分析（两阶段流水线）
- **Stage 1 信息抽取**：把候选新闻压缩成结构化要点（带 [N] 编号）
- **Stage 2 全局分析**：注入用户画像 + 订阅关键词，生成「机会 / 风险 / 行动建议」的定制解读，正文引用都用 [N] 编号对应下方原始新闻
- 为什么不一步到位？抽取+分析分离让模型每步任务单一，输出更稳、更省 token

### 4. 溯源与可信度
- **每条 AI 结论都对应原始新闻**：点击即可看到来源、可信度、交叉验证状态
- **信源可信度分级**（1-10）：官方媒体 10 / 权威媒体 9 / 专业媒体 7 / 科技媒体 6 / 社区与自定义 4——是"媒体评级"而非"内容真实性"，多源交叉验证（同事件 ≥2 独立信源）会额外打标

### 5. 定时送达与防重
- 订阅存 cron 表达式（北京时间），Celery beat 每 60 秒巡检到期订阅 → 派发 worker 生成 → SMTP 发送
- **四层防重**：10 分钟窗口去重 / 运行中任务跳过 / 24 小时过期窗口不补发 / 任务状态全程落库（TaskRun）

## 三、可靠性设计（"定时邮件不掉链子"）

| 故障 | 保障 |
|---|---|
| 容器崩溃 | Docker restart 策略 + 每 5 分钟健康巡检自动重启 |
| beat 宕机恢复 | 24h 内到期补发，超 24h 滚动跳过（不轰炸用户） |
| 任务挂死 | 软超时 10 分钟 / 硬超时 15 分钟强杀 |
| 服务重启 | watchdog 每 15 分钟自愈孤儿任务 |
| 邮件发送失败 | 自动重试 1 次 + 失败告警邮件通知管理员 |
| 数据丢失 | 每日 03:00 自动 pg_dump 备份（保留 7 份） |

## 四、行业问答标准答案（面试/交流用）

**Q1：这和普通新闻 App 有什么区别？**
新闻 App 是"人找信息"（主动刷、算法推大众热点）；我们是"信息找人"——按你的身份和关键词定制，定时投喂到邮箱，每条可溯源。本质是从"信息检索工具"变成"个人情报系统"。

**Q2：和市面上 AI 新闻摘要工具有什么不同？**
三个差异：① **可溯源**——每条结论必须能点回原始新闻，AI 说错了能查证；② **多源交叉验证**——同事件多家信源才打可信标；③ **身份视角**——同一新闻对考研党/投资者/创作者给出不同解读。

**Q3：AI 会不会一本正经地胡说八道？**
会，任何大模型都会。所以我们的设计哲学是"**AI 会出错，让它无处可藏**"：结论必带出处编号、信源可信度透明、多源验证打标、免责声明明确"AI 输出不等于事实"。把判断权还给用户。

**Q4：定时发送怎么保证不丢不重？**
Celery beat 调度 + 持久化任务状态 + 四层防重 + 失败告警 + 容器自愈 + 每日备份。多副本部署时调度器单实例（文件锁/独立 beat 容器），worker 可横向扩展。

**Q5：用户数据安全吗？**
密码 bcrypt 哈希（不可逆）、API Key AES-256 加密存储、JWT 无状态认证、全程 HTTPS、不向第三方共享数据、每封邮件带退订链接。隐私政策 9 章覆盖。

**Q6：商业模式是什么？**
目前免费（平台承担 AI 成本）。但**计费基础设施已就绪**：每份简报消耗 1 额度、月度配额、订阅级预算上限、超支自动暂停+通知——将来可平滑切换按量付费/订阅制。

**Q7：为什么选邮件而不是 App？**
三个理由：① **反算法**——邮件没有推荐算法绑架，每天就一封；② **零打扰**——没有推送轰炸，读完即走；③ **天然留存**——简报躺在收件箱，随时回看溯源。

**Q8：技术上最难的几个点？**
① 新闻语义归并（同事件多源识别）；② 中文关键词分词匹配（用户输入中英文逗号/长短语都能命中）；③ AI 输出可靠性工程（抽取-分析两阶段、重试、输出清洗）；④ 邮件在 QQ 邮箱等客户端的排版兼容（纯 div 结构+内联样式的血泪经验）；⑤ 定时链路零丢失（防重/自愈/告警闭环）。
